Amendments 134, 136 and 137 stand except where this one says otherwise. No run before the Overseer's check and GO.

**Why.** kj1 (amendment 137) failed J6 and J7 on our side from one cause. A creature was killed in ITR2 while X-Ray
was stopped. X-Ray's first snapshot after the stop carried `k,<id>,…,dead` (its kill call was made) while the
creature's own line still read alive at health 0.0008. The mod took the `dead` line as the confirmation, closed its
report, and the living line in the same snapshot made it spawn the puppet again; 0.10 s later the creature read dead
and the puppet was removed. EnginePerf found the same two snapshots in their kept bytes. The fault is in what a
`dead` line may mean; it gets one rule in the format and a guard on our side.

**The format (joint; replaces the sentences on the `dead` line in amendment 134; the version stays 4).**
1. X-Ray writes `k,<id>,<applied>,dead` only when, as the snapshot is built, the creature reads dead (its `o` line
   has alive 0) or no object exists for the id. A kill call that was made but is not yet in effect writes the plain
   line `k,<id>,<applied>` (the applied count already holds the last piece). So a `dead` line and an `o` line with
   alive 1 for the same id never stand in one snapshot.
2. New word: `k,<id>,<applied>,stale`. The id is listed but is not the creature of our line (another section, or
   alive again after its death was confirmed more than 10 s ago). The mod drops its line, counts it stale and never
   counts it a confirmation. With the line gone the id is no longer held back: a living creature under that id is
   shown again, as any other creature X-Ray lists. An id with no object is answered as in
   amendment 134, unchanged: a `dead` line carrying the applied total X-Ray holds for it (for example
   `k,106,0.300,dead`), and `0.000` only when X-Ray holds nothing for the id at all.
3. The `r` line is unchanged. "Processed" no longer implies that the `dead` line is in that same snapshot; it may
   come one or more snapshots later. Our 10 s rule (amendment 134) runs from `r` as before: an online kill that never
   takes effect ends as `KILL not applied` and the mod follows X-Ray.
   On X-Ray's side an online kill whose creature still reads alive 2.0 s (X-Ray script time) after the call is
   logged and counted (`kdead_fail`); its line stays the plain line. If the creature reads dead later all the same,
   the `dead` line is written then.
4. Older software: a mod without this amendment reads `stale` as a plain line (it never drops by it; harmless). An
   X-Ray reader without it is kj1's fault. Both sides are pinned anew; no version step.

**Who guards.** X-Ray keeps rule 1 (EnginePerf's reader; their test and mutant). The mod guards it as well: a death
report closes only on a `dead` line whose creature, in that same snapshot, reads dead (alive 0) or is not listed.
Dead means X-Ray's alive field alone, on both sides: EnginePerf's rule 1 tests the object's alive state as the
snapshot is built, and under version 4 our reader takes a creature printed at alive 1 as living whatever its health
prints (X-Ray lets a creature stand at health 0 or below for a frame; 4 decimals can print 0.0000). The puppet rule
follows the same reading. A `dead` line beside a living creature line is counted (`dead_beside_alive=N` at the end of
the `KC end` line), logged once per report (`KC dead line beside a living creature id=… snap=…: not acted on`), and
nothing is closed, dropped or spawned by it; the same holds for a part-hit line of ours. Nothing is remembered from
it: a later snapshot needs its own `dead` line. A creature line alone, with no `dead` line, never closes a report
(as before: X-Ray's own world may have hurt it).
