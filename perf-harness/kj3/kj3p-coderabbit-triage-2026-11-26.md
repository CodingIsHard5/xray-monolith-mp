## Extra (coordinator): runner line 56, an exit-code way to ask "a claim is held"
There is none. I read ~/.claude/overseer/tools/quiet-required.sh read-only, and no read-only verb answers this question by exit code alone:
- `check`: exit 0 when ANY worker holds slot 1 (:1605-1626). It says nothing about who holds it or whether it is EXCLUSIVE or B1-T2, and that is exactly what line 56 greps the HELD text for.
- `blocked <w> [what]`: exit 1 both for "you hold slot N" and for a free box ("not blocked", :1529, :1536, :1575). For the holder it also exits 0 ("HOLD OFF") while Caden is gaming, because admission() returns 4 before its own-slot return (:933-935).
- `clear <w>`: exit 0 both when <w> holds a slot (ADMIT_VIA own) and when the box is free (:1580-1584).
- `renew <w>`: exit 0 only if <w> holds a live or just-expired slot (:983). But it WRITES: it extends the claim (default 60 min) and can replace its <what>. It is not a query.

The nearest exit-code line would be `"$HOME/.claude/overseer/tools/quiet-required.sh" check >/dev/null 2>&1 || { log "REFUSED: no claim held"; exit 2; }`. I do not recommend it: it drops the EXCLUSIVE / B1-T2 condition that the text match enforces. Keeping line 56 as it is, or adding a read-only verb to quiet-required.sh (for example `holds <w>` returning exit 0 iff slot_of/holder is <w>), are the options. Both are the Overseer's call, and I edited neither file.

## Not covered / limits of these fixes
- The driver's main body has never run end to end. Not executed: kill_own on a real Wine engine, `wineserver -k`, kill_watcher, the caden-play lock refusal, and the after-claim re-checks. Their order is checked statically.
- kj3p_score.sh hashes the checker a few ms before python opens it. A change inside that window would not be caught.
- The worker name `engineperf` is shared with EnginePerf's own session. If that session already holds a claim under the same name, `claim` succeeds as "own" and this driver's finish would release it. Not handled. The driver assumes no other engineperf claim is held.
- The P2 bound uses kj2's measured ages (an ITR2-fed run) and the kw1 writer's 50 ms period. No kj3p-writer run has measured them on the box.
