## 1. Desk audit of shared state (Opus sub-agent, read-only; key claims re-checked by me on disk)
Cascade graph managers use the mask {deferred, shmap} with fl_normal false and i_options 0 (r_sun_cascades.h:38), so
HOM, SSA, fade, ROS and the lighting tracks are not reached on the cascade path. Findings:
- SAFE for workers: the cascade TRAVERSE plus r_dsgraph_capture_static. Portal traverser state is per manager
  (r__dsgraph_manager.h:17-41). Sectors and portals are read-only. Spatial q_frustum is under a shared lock. Camera and
  ssa globals are set before render. Particle groups are under onframe_lock.
- RACE, must fix: the global `phase` picks the shader element in rimp_select_sh_static/dynamic (VERIFIED r4.cpp:72-86,
  `if (CRender::PHASE_NORMAL == RImplementation.phase)`). Main writes it while tasks would read it. Fix: give each
  manager its own phase (or use its fl_normal mask) and pass it to rimp_select_*. `phase = PHASE_SMAP` stays on main
  before submission. About 15 lines.
- RACE, only with stats on: the PortalTraverse debug statics (r__dsgraph_manager.cpp:11-12). Fix: thread_local, or no
  stats while MT. About 3 lines.
- NOT SAFE, kept on main: r_dsgraph_capture_dynamic (VERIFIED: a separate function, r__dsgraph_render.cpp:603). It calls
  game objects' renderable_Render, which writes XFORMs, weapon lights, crow lists and leg transforms, and the actor
  reads the global active_phase (VERIFIED Actor.cpp:2256). In 1b-1 the dynamic half runs on main, serially, in
  cascade order.
- Latent bug found (NOT fixed in 1b-1, recorded for BUGFIXES): r__sector.cpp:191
  `DM.i_options & VQ_FADE | VQ_SSA && ...`. The precedence makes it always true when rsDrawPortals is on (VERIFIED).
  Debug-only (portal drawing); fixing it is a separate small Rule Two fix.
- Already in the engine, unused: xr_task_group sun_cascades_task (VERIFIED r4.h:206, no uses). 1b-1 uses it.
- ORDERING HAZARD found by me (desk): each cascade's prepass writes the shared sun light's fuckingsun->X.D (min/max,
  then combine in Finalize). So prepass i must still come right before finalize i, or the per-cascade values must be
  saved and restored. The tasks need only cascade.cull_frustum/COP/xform, which are already per cascade. The build will
  split the prepass into "compute this cascade's frustum" (moved before the tasks) and "write fuckingsun->X.D" (left in
  place), and the pixel check catches any mistake.

## 3. Share and prediction
From the step-1a K0 runs (flat profile): the cascades' capture is 0.343 ms in Rostok. The static half for the cascades is
bounded: >= 0.343 - 0.215 (all dynamic capture) = 0.13 ms, and < 0.344 (all static capture, main scene included). So
S_static is in [0.13, 0.34) ms in Rostok and [0.04, 0.11) in Cordon. The switch-OFF arm measures it exactly.
With three tasks in parallel and main waiting at the join, the gain is S_static minus the largest cascade's share,
minus task overhead (about 0.01-0.02).
PREDICTED main-thread gain: Rostok 0.06-0.22 ms, central 0.12. Cordon 0.01-0.06. This is SMALL: about 2 % of the Rostok
frame, near the frame-time repeat spread (2.8 %, about 0.16 ms). Its value is mainly as a first step toward 1b-2.

## 4. Bars and stop rules
- Bar A (measured on the switch-OFF arm of the same exe, before any ON run is scored): the cascades' static share
  S_static >= 0.15 ms in Rostok. If lower, 1b-1 STOPS without scoring ON, and I bring 1b-2 to the Overseer directly.
- Slice rule: STOP R1b if the measured main-thread gain in Rostok is < 1/4 of the central prediction (< 0.03 ms).
- 1b-2 STOP RULE (registered here, as the Overseer ordered): 1b-2 is planned ONLY if 1b-1's measured gain in Rostok is
  >= 1/2 of its central prediction (>= 0.06 ms). Between 1/4 and 1/2: no 1b-2; I report and the Overseer decides.

## 5. Checks (the full list)
1. Image equality: frame dumps on fixed camera paths (Rostok, Cordon, one with the sun low), switch OFF against ON,
   pixel-identical, shadow maps included. No tolerance.
2. Tier (a): -det_mode counters equal to RefDet14 with the switch ON.
3. Main-thread time and frame time. NEEDS OK: the PRIMARY gain metric is main-thread render-feed time ("Process
   seqRender" inclusive, spread < 0.03 ms), because a 0.12 ms gain cannot clear the 0.16 ms frame-time spread. Frame
   time must be no worse: mean within the spread of the OFF arm, p99 not worse. Rostok and Cordon, 3 OFF + 3 ON each,
   interleaved, same exe.
4. A 4-core pinned repeat (Rostok, 1 OFF + 1 ON): main-thread time not worse with ON.
5. Absence: no per-frame-number cache (code search); cascade order unchanged; in r_stereo_bench 2, eye 1 starts no tasks
   (code read plus a log line); the stereo smoke run done by gammavr on my commit hash.
